# 發布與密碼鎖計畫

> 狀態：**規劃完成，尚未實作**。等遊戲內容完成後，作為正式上線前的最後一步再做。
> 記錄日期：2026-10-20

---

## 一、目標

- 沒有輸入作者給的密碼之前，**只能玩第一章**。
- 密碼**無法被暴力破解**。
- **一組密碼只能在一台裝置上使用**，確保每位玩家都是拿到作者發的隨機密碼才能玩。

## 二、已經決定的事

| 項目 | 決定 |
|---|---|
| 上線方式 | 使用 Cloudflare（免費方案），**留到遊戲完成後的最後一步** |
| 遊戲網址 | 遊戲尚未發布，網址可以在部署時再決定（決定後就不要再改，存檔跟著網址走） |
| 換裝置 | 每組密碼**自動允許換 1 次裝置**；再換就要由作者手動「解除綁定」 |
| 本機版 | **保留**雙擊 `index.html` 遊玩；第二章以後一樣要連網啟用一次 |
| 測試用密碼 | 一組**不限次數、不限裝置、不限時間**的測試密碼，只有作者查得到，可以隨時更換 |
| 開發電腦 | 作者在公用電腦上開發：**電腦上不留任何敏感資料**，每次操作完自動登出 Cloudflare |

## 三、⚠ 上線前一定要先處理

1. **把 GitHub 專案改成私人（Private）**
   目前 `github.com/58peiShan/singforyou` 是**公開**的，所有章節的劇本（`script/*.md`、`game/data/script.js`）任何人都看得到。密碼鎖只保護遊戲，保護不了 GitHub 上的原始檔。
   步驟：打開專案頁 → **Settings** → 最下面 **Danger Zone** → **Change repository visibility** → **Make private** → 依指示輸入專案名稱確認。
   （這一步不需要等遊戲完成，越早做越好。）
2. **密碼鎖完成前，不要把 `game` 資料夾上傳到任何公開網站**
   現在的 `game/data/script.js` 含有全部章節的文字，上傳後任何人都能直接讀到。

## 四、運作方式（白話版）

1. **章節加密**：部署時，第二章以後的劇本會被加密。加密後的檔案就算公開也只是亂碼；解密金鑰是隨機產生的，只存在作者的 Cloudflare 帳號裡。
2. **作者發密碼**：作者執行「產生密碼」，得到一批像 `7K3M-Q9XD-2RTV-8HWN` 的隨機密碼（16 個字，不含 0/O、1/I 等易混淆字元），一人一組發出去。
3. **玩家解鎖**：玩家玩完第一章，或在標題畫面按「輸入密碼」後輸入密碼。手機會在本機產生一把無法被複製出來的「裝置金鑰」，連同密碼送到伺服器。
4. **伺服器判斷**：
   - 密碼沒用過：綁定這台裝置，交出解密金鑰。
   - 已綁定這台裝置：直接交出金鑰（例如重新安裝）。
   - 已綁定別台、但還沒換過裝置：改綁到新裝置，舊裝置下次連網時會自動停用。
   - 已經換過一次：拒絕，請玩家聯絡作者。
5. **之後離線也能玩**：金鑰會存在玩家的裝置上，不用網路也能玩。裝置每次連網開啟時會重新確認一次；超過 30 天都沒連網，就要連網確認一次才能繼續玩第二章以後。

### 為什麼無法暴力破解
- 密碼有 80 位元的隨機性：每秒試一百萬次，也要幾百億年。
- 伺服器限速：同一個網路位址每小時最多猜錯 10 次，全站每小時最多 1000 次。
- 解密金鑰是 256 位元隨機值，不是由密碼推算出來的，所以拿到加密檔也無法在自己電腦上破解。

### 誠實的限制
- 「一台裝置」實際上是**一台裝置上的一個瀏覽器**。清除瀏覽資料、換瀏覽器、換手機，都算換裝置（會用掉那 1 次機會）。
- iPhone 若沒有「加入主畫面」，Safari 可能在 7 天沒開啟後清掉網站資料，等於換裝置 → **要請 iPhone 玩家加入主畫面後再解鎖**。
- 能確保「每個人都要拿到密碼才能玩」，但擋不住已解鎖的人用技術手段把文字抄出來。網頁遊戲沒有辦法做到完全防拷。
- 舊裝置換掉後，如果一直不連網，最多還能再玩 30 天才會被停用。
- 第一次解鎖一定要有網路。

## 五、作者在上線時要做的事

**一次性（約 15 分鐘）**
1. 到 `dash.cloudflare.com/sign-up` 註冊（email＋密碼，不需要信用卡），開啟兩步驟驗證。
2. 確認 GitHub 專案已改成私人（見第三節）。
3. 雙擊 `首次設定.bat`：瀏覽器會打開 Cloudflare 登入頁 → 登入 → 按「Allow」。程式會自動建立資料庫、上傳遊戲、產生測試密碼，最後顯示遊戲網址。
4. 用自己的手機實際測一遍：玩完第一章 → 輸入測試密碼 → 解鎖；再用一組一般密碼測換裝置被擋下的情況。

**之後日常（都是雙擊）**

| 檔案 | 用途 |
|---|---|
| `部署.bat` | 改完劇本後，加密並上傳新版本 |
| `產生密碼.bat` | 產生 N 組新密碼（可以加備註，例如發給誰） |
| `查詢密碼.bat` | 看每組密碼的狀態：未使用／已啟用／已換過裝置／停用 |
| `解除綁定.bat` | 玩家換手機用完機會時，幫他重設 |
| `停用密碼.bat` | 密碼外流時讓它失效 |
| `測試密碼.bat` | 查看或更換測試用密碼 |
| `備份.bat` | 把密碼與綁定紀錄加密匯出（需設定備份密碼），存到 `備份/`，可以安全地放進 git |
| `打包本機版.bat` | 產生給玩家下載、雙擊就能玩的壓縮檔（第二章以後是加密的） |

每個 `.bat` 執行時都會請你登入 Cloudflare，結束時自動登出，不會在公用電腦上留下登入狀態或密碼清單。

## 六、實作清單（給之後實作時參考）

### 建置（`tools/build.js`）
- 公開版 `game/data/script.js` 只放主線第一個檔案的完整內容；其餘檔案（含人魚篇）只留 `{key, name, route, num, title, locked: true, ops: []}`，索引不變，`labels` 照舊。
- 另外輸出 `game/data/script.dev.js`（`window.GAME_DEV = {files: [{i, key, ops}]}`），只供作者本機雙擊時使用；加入 `.gitignore`，部署與打包時排除。
- `GAME_DATA.lock = { api: <tools/cloud.json 的網址>, count }`。
- **注意**：建置拆分、遊戲端解鎖程式、引擎的鎖定檢查必須**同一次**完成，否則第二章以後會讀不到。

### 遊戲端（新增 `game/js/lock.js`，修改 `engine.js`、`ui.js`、`index.html`、`sw.js`）
- `index.html`：雙擊開啟（`file:`）時載入 `data/script.dev.js`（有的話）；一律嘗試載入 `data/script.locked.js`。
- 裝置金鑰：WebCrypto ECDSA P-256、**不可匯出**的私鑰存在 IndexedDB；IndexedDB 不能用時，退回 localStorage 存可匯出的金鑰。
- 內容金鑰：AES-256-GCM，以不可匯出的 `CryptoKey` 存在 IndexedDB；另存 `{code, kid, verifiedAt}`。
- 開機：有 dev 全文 → 直接開放（標題畫面註明「開發模式」）；有金鑰且 30 天內驗證過 → 立即解密；背景連網驗證，回傳「已移到別台／密碼不存在」就清除金鑰並提示。
- 引擎：`_loop` 碰到 `locked` 檔案時先在該章開頭自動存檔，再呼叫解鎖對話框；`E.load()`、`E.startSide()` 碰到鎖住的章節同樣先要求解鎖。
- 介面：解鎖對話框（羊皮紙＋金框、輸入框自動大寫並每 4 字加 `-`、錯誤訊息用 `role="alert"`、輸入框要加 `user-select: text`，否則 Safari 無法輸入）；標題選單在鎖住時以「輸入密碼」取代「人魚篇」（維持 6 顆按鈕）；設定加「完整版」狀態列。
- `sw.js`：CORE 加入 `data/script.locked.js` 並更新快取版本。

### 伺服器（Cloudflare Pages Functions＋D1，同一個專案、同一個網址）
- `functions/api/activate.js`、`functions/api/verify.js`；共用程式放 `server/lib.js`（不要放在 `functions/` 裡，以免變成網址）。
- 請求內容：`{code, pub: {x, y}, ts, sig}`，`sig` 是裝置私鑰對 `"activate|CODE|ts"`（或 `verify|…`）的簽章；伺服器用 `pub` 驗章，裝置識別碼＝`pub` 的 SHA-256 指紋。
- 回應加 `Access-Control-Allow-Origin: *`（給雙擊開啟的本機版用）；前端用 `Content-Type: text/plain` 送 JSON，避免預檢請求。
- 綁定更新要用條件式 `UPDATE … WHERE device IS NULL`／`WHERE device = 舊值`，避免兩台同時啟用的競爭狀況。
- D1 資料表：
  - `codes(code PK, note, unlimited, disabled, created_at, device, activated_at, changes, prev_device, moved_at, last_seen, uses)`
  - `config(k PK, v)`：存內容金鑰與 `kid`
  - `attempts(bucket PK, count, expires)`：限速，只記失敗次數
- 密碼字元集：`23456789ABCDEFGHJKLMNPQRSTUVWXYZ`（32 個），16 字＝80 位元；輸入時轉大寫並去掉空白與 `-`。

### 管理工具（`tools/cloud.js`＋上面那些 `.bat`）
- `package.json` 固定 `wrangler` 版本（規劃時選定 `4.146.0`，發布於 2026-10-01）；直接用 `node node_modules/wrangler/bin/wrangler.js` 呼叫，不經過 `npx`。
- 環境變數 `WRANGLER_SEND_METRICS=false`，避免第一次執行跳出詢問。
- 每個指令：`whoami` → 未登入就 `login` → 執行 → **一律 `logout`**（放在 finally）。
- 部署：重新建置 → 從 D1 讀內容金鑰（只放在記憶體，不寫檔）→ 把 `script.dev.js` 的內容加密成 `dist/data/script.locked.js` → 複製 `game/` 到 `dist/`（排除 `*.dev.js` 與其他測試資料）→ **掃描 `dist/` 確認沒有第二章以後的原文，有就中止** → `wrangler pages deploy dist`。
- 金鑰更換時，已解鎖的裝置會在下次連網驗證時自動拿到新金鑰，不必重新輸入密碼。
- 備份：使用者輸入備份密碼（至少 10 字），以 scrypt＋AES-256-GCM 加密成 `備份/潮約之歌-備份-日期.enc`；另外做還原指令。

### 實作時要先確認的事（規劃時尚未驗證）
- `wrangler d1 create` 的輸出格式，以及會不會跳出「要不要幫你寫入設定檔」的詢問（以 `wrangler d1 list --json` 取得資料庫 ID 較穩）。
- `wrangler d1 execute --remote --file` 會不會要求確認，以及有沒有 `--yes` 參數。
- `wrangler pages deploy` 是否從專案根目錄的 `functions/` 與 `wrangler.toml` 讀取 Functions 和 D1 設定。
- 專案名稱已被別人用掉時，`*.pages.dev` 網址可能會被加上隨機字尾 → 以部署結果顯示的網址為準。
- D1 免費方案的時間回溯（Time Travel）保留天數。
- Safari／Firefox 雙擊開啟時，WebCrypto 與 IndexedDB 是否可用（Chrome 已確認可用）。

### 已確認的事（2026-10-20）
- Chrome 雙擊開啟（`file://`）時：`isSecureContext` 為 true、`crypto.subtle` 可用、ECDSA P-256 可用，IndexedDB 可以儲存不可匯出的 `CryptoKey`。
- 這台電腦可以從 npm 安裝 wrangler（Node v22.17.0），可以在本機用 `wrangler pages dev` 模擬伺服器，**先完整測試、再請作者註冊帳號**。
